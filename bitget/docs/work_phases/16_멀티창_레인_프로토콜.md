# Bitget 멀티 창 · 레인(Lane) 프로토콜

> **문제**: Bitget 폴더 안에서 Cursor 창 2개가 동시에 일하면 `NEXT_ACTION` / `09` / `CURSOR_TO_CLAUDE`를 **통째로 덮어써** 최신이 섞인다.  
> **해결**: **공유 대시보드(표만)** + **레인별 전용 폴더(본문)** — 창은 자기 레인만 쓰고, 남의 레인 파일은 **읽기만**.

---

## 1. 한 줄 규칙

| 규칙 | 내용 |
|------|------|
| **한 창 = 한 레인 = 한 sub-phase** | 예: 창A=`LANE_FASTCHECK` · 창B=`LANE_HIST3FIX` |
| **본문 쓰기** | `lanes/<LANE_ID>/` **만** (OUTBOX·NEXT·09·NEXT_STEP) |
| **공유 파일** | `ACTIVE_LANES.md` · `NEXT_ACTION.md` · `00_SESSION_SYNC` §3 = **표 행만 upsert** · 다른 행 **삭제·덮어쓰기 금지** |
| **05_진행로그** | **섹션 append만** · 다른 sub-phase 섹션 수정 금지 |
| **CLAUDE_TO_CURSOR** | **prepend/append만** · 기존 블록 삭제 금지 |
| **코드(.py)** | 레인과 무관 — Handoff 범위의 `bitget/**`만 · 본 프로토콜은 **MD 혼선 방지** |

---

## 2. 폴더 구조

```
bitget/docs/work_phases/
  16_멀티창_레인_프로토콜.md          ← 본 파일
  lanes/
    ACTIVE_LANES.md                   ← 열린 레인 표 (모든 창이 갱신)
    LANE_FASTCHECK/                   ← B1-LADDER-R1a-FASTCHECK 전용
      CURSOR_TO_CLAUDE.md
      NEXT_ACTION.md
      NEXT_STEP.md
      09_쉬운요약.md
    LANE_HIST3FIX/                    ← FULL-BT-HIST-3-FIX 전용
      CURSOR_TO_CLAUDE.md
      NEXT_ACTION.md
      NEXT_STEP.md
      09_쉬운요약.md
  NEXT_ACTION.md                      ← 대시보드(레인 요약 표만)
  CURSOR_TO_CLAUDE.md                 ← 인덱스 + “어느 레인 OUTBOX를 볼지”
  09_디렉터_쉬운요약.md                 ← 인덱스(레인별 한 줄 + 링크)
```

신규 병렬 작업 시: `lanes/LANE_<짧은ID>/` 폴더를 만들고 `ACTIVE_LANES.md`에 행 추가.

---

## 3. 세션 시작 (Cursor)

1. `lanes/ACTIVE_LANES.md` — **내 레인 ID** 확인(없으면 디렉터에게 레인 배정 요청)
2. `lanes/<내레인>/NEXT_ACTION.md` — status
3. `CLAUDE_TO_CURSOR.md` 최상단에서 **내 sub-phase Handoff만** 구현
4. **금지**: 다른 레인의 `CURSOR_TO_CLAUDE` / `09` / `NEXT_*` 덮어쓰기

첫 메시지에 적기 권장:
```
레인: LANE_FASTCHECK · sub-phase: B1-LADDER-R1a-FASTCHECK · bitget MD만 이 레인
```

---

## 4. 세션 종료 (Cursor)

1. **레인 폴더만** 본문 갱신: `lanes/<ID>/CURSOR_TO_CLAUDE.md` · `NEXT_ACTION` · `NEXT_STEP` · `09`
2. `lanes/ACTIVE_LANES.md` — **내 행만** status/날짜 upsert
3. 루트 `NEXT_ACTION.md` — 대시보드 표에서 **내 행만** 맞춤
4. 루트 `CURSOR_TO_CLAUDE.md` — 상단에 **인덱스 2~4줄**(어느 레인 OUTBOX가 최신인지)만 · 본문은 레인 파일
5. 루트 `09` — 레인별 한 줄 요약 표만
6. `05` — **내 sub-phase 섹션 append/갱신**만
7. `00_SESSION_SYNC` §3 — 열린 줄기에 레인 ID 명시

## 5. 디렉터 · Claude Knowledge 업로드

- **코드(.py) 제외** 업로드 시: `lanes/*/`, `09`, `NEXT_*`, `CURSOR_TO_CLAUDE`(인덱스), `ACTIVE_LANES`, `13_`(해당 시), `05` 해당 섹션
- Desktop 미러: `Desktop/클로드 작업/bitget_upload_YYYYMMDD/` (본 프로토콜이 복사 대상)
- Claude에게: 「레인 LANE_XXX 의 OUTBOX 검증」— **다른 레인 파일과 섞어 읽지 말 것**

---

## 6. 충돌 시

| 증상 | 조치 |
|------|------|
| 루트 `NEXT_ACTION`에 내 일이 사라짐 | `lanes/<ID>/NEXT_ACTION.md`가 **진실** · 루트 표에 행 복구 |
| 루트 OUTBOX가 다른 창 내용만 있음 | `lanes/<ID>/CURSOR_TO_CLAUDE.md`가 **진실** |
| 두 창이 같은 레인 | **즉시 중단** · 디렉터에게 레인 재배정 |
