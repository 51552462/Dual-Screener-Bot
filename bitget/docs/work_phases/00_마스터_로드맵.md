### 4GB RAM 서버 — 코인 메모리 예산 (주식과 공존 시)

서버 **전체 4GB**이면 코인 스택에 **cgroup 상한 필수** (주식 OOM 연쇄 방지):

| 유닛 | 권장 MemoryMax (4GB 서버) | 비고 |
|------|---------------------------|------|
| `dante-bitget-factory` | **768M ~ 1G** | 스캔·pandas 피크 |
| `dante-bitget-ws` | **192 ~ 256M** | |
| `dante-bitget-async` | **96 ~ 128M** | |
| `dante-bitget-dashboard` | **256 ~ 384M** | 필요 시만 기동 |
| `dante-bitget-heatmap` | **192 ~ 256M** | 필요 시만 기동 |
| **코인 합산 목표** | **≤ 1.5 ~ 1.8 GB** | OS + 주식 여유 2GB+ |

```bash
# drop-in 예시 (서버 1회 설정, git pull과 무관)
sudo mkdir -p /etc/systemd/system/dante-bitget-factory.service.d
sudo tee /etc/systemd/system/dante-bitget-factory.service.d/memory.conf <<'EOF'
[Service]
MemoryHigh=700M
MemoryMax=896M
CPUQuota=80%
EOF
sudo systemctl daemon-reload && sudo systemctl restart dante-bitget-factory
```

환경 변수 (`.env` 또는 drop-in): `BITGET_MAX_WORKERS=2~4` (4GB 서버)

**상세**: `bitget/docs/10_single_server_resource_management.md`, `09_ubuntu_deployment_and_update_guide.md`

## 2. 진단 요약 (왜 Bitget paper가 ‘무인 복리’에 아직 못 미치는가)

> 출처: `bitget/docs/13_institutional_grade_audit_and_roadmap.md` (2026-07)

1. **가상매매만** — 슬리피지·펀딩·실체결 미반영 → 리포트 PnL은 낙관적일 수 있음
2. **Portfolio NAV 서킷브레이커 부재** — 그룹 −30%만 있어 동시 손실 시 계좌 전체 −25%도 통과 가능
3. **deathmatch 자본배분 꺼짐** (`apply_deathmatch_allocation=False`) — 나쁜 전략이 굶지 않음
4. **market key 불일치** (`BG` vs `SPOT`/`FUT`) — 진화·Meta 정합성 약함
5. **tail-risk fund 적립만** — drawdown 시 실제 흡수·트리거 없음
6. **로그 무제한 증가** — 4GB RAM·80GB SSD 서버에서 **수개월 방치 시 디스크 고갈** (P0-1)
7. **24/7 코인** — 장 휴장 없음 → cron 27슬롯·WS·메모리 피크가 **주식보다 지속적** (리소스 cap 필수)
8. **실전 경로 미완** — exit 실주문·funding PnL·parity 없이 `ENABLE_REAL_EXECUTION=true` **금지**

주식 진단(롱 모멘텀 편중·KR 장중 슬롯·MDD 10%)은 **참고만** — Bitget은 **24/7·레버리지·펀딩·WS** 가 추가 변수.
