## 2. 렁 표 R0~R6

**순서 고정:**  
`R0 → R1 → R2 → (A 06 판정) → R3 ∥ R4(병렬 가능) → R5 → R6`

| 렁 | 내용 | Critical? | 착수 조건 | 비고 |
|----|------|-----------|-----------|------|
| **R0** | 본 SSOT 문서화 (성공계약·렁·Kill·승인문구) | 🟢 문서 | — | **본 sub-phase** |
| **R1** | OPEN 처리량 · 퍼널 진단 (아래 R1a/R1b) | 관측→mini | R0 후 | 코드는 별도 세션 |
| **R2** | `06` 효과표 2~4주 채움 | 관측 | R1 진행 중·후 | A/B shadow 유지/롤백 |
| **R3** | MDD tier ~3/~4/**5%** + Kelly↓ + lev≤3 | 🔴 | **A 06 1차 통과 후** | 프로필 전환 |
| **R4** | C-2 funding PnL (close 오염 해소) | 🔴 | R3와 **병렬 가능** | 데이터 vs 정책 독립 |
| **R5** | deathmatch alloc **live** | 🔴 Go/No-Go | **R3 완료** + shadow 4주 무결함 | 5% 예산 위 배분 |
| **R6** | L2 판정: trades≥30 · ≥56일 · rolling MDD≤5% · 페이스 | 게이트 | R3+R4+R5 **반영 데이터** | G2/G3 정합 (NS-1) |

### R1 분해 (다음 세션 후보 · 이번 R0 코드 대상 아님)

| sub | 내용 | 선행 |
|-----|------|------|
| **R1a** | POST_DEPLOY_OBS 등으로 OPEN=0이 **냉시동 정상** vs **구조적 막힘** 판별. I-GMM-DNA-01 이미 배포 — **신규 코드 불필요**, 서버 실측 재확인 | 없음 · **관측만** |
| **R1b** | R1a에서 구조적 막힘 확정 시에만 — DNA/Cos/게이트/국면 원인 **CAT-C mini Handoff** | R1a FAIL 확정 후 |

### R3~R5 Critical 승인문구 템플릿 (구현 지시 아님 · 향후 Handoff용)

| 렁 | 디렉터 승인 문구 (그대로 표기) | 의존성 |
|----|-------------------------------|--------|
| **R3** | 🔴 Critical R3 승인: MDD tier REDUCE~3/BLOCK~4/HALT5%, Kelly↓, lev≤3 프로필 전환 승인. 롤백조건: NAV MDD 실측 악화 시 A-1 15/20/30% tier로 즉시 복귀. | A 06 1차 통과 후 |
| **R4** | 🔴 Critical R4 승인: C-2 funding PnL 반영, close PnL 오염 해소 승인. 롤백조건: funding 반영 후 paper CAGR 급락 시 표시 전용 롤백(회계만 원복). | R3와 병렬 가능 |
| **R5** | 🔴 Critical Go/No-Go R5: deathmatch alloc live(`apply_deathmatch_allocation=True`) 승인. 전제: R3 활성 + shadow 4주(B-2) 무결함. | R3 완료 후에만 |

**R6 전제:** B1 판정은 반드시 **R3+R4+R5 셋이 반영된 데이터**로만.  
정합: NS-1 G3 = A06+C2+MDD4주 (신규 발명 아님).

## 3. Kill 기준표

| 렁 | FAIL 조건 | 행동 (Kill) |
|----|-----------|-------------|
| **R1** | 4주 경과해도 OPEN 지속 0 (냉시동 아님 확정) | R2 착수 금지 · 원인 mini-Handoff 추가 |
| **R2** | `06` NAV MDD 악화 관측 | **무조건 롤백** (`06` 하단 원칙 재사용) |
| **R3** | tier 적용 후 실측 MDD 여전히 초과 | A-1 15/20/30%로 즉시 복귀 · B1 목표 재검토(→B0 하향 가능) |
| **R4** | funding 반영 후 CAGR 12% 미달 | 성공계약 재협상 → 디렉터 에스컬레이션 |
| **R5** | shadow 4주 중 NAV MDD 영향 / 루저 자본 훼손 | live 보류 · `apply_deathmatch_allocation=False` 유지 |
| **R6** | trades&lt;30 또는 &lt;56일 또는 rolling MDD&gt;5% | B1 「달성」 **미판정** · 관측 연장 |

### R1a 판정 절차 (B1-LADDER-R1a · 문서 전용 · 신규 코드 없음)

> R0 확정일 앵커: **2026-08-23**. 매주 재관측. 신규 상수 없음 — FAIL (a)의 **4주**는 위 Kill 표 R1 행 재사용.

| 판정 | 조건 | 행동 |
|------|------|------|
| **PASS** | 신선 실측에서 **OPEN&gt;0** 신규 진입 확인 | R2 착수 (효과표 채우기 시작) |
| **관측 유지** | OPEN=0 지속 **AND** R0 확정일로부터 **4주 미만** 경과 **AND** 구조적 거절 증거 없음 | Kill 미발동 · 주간 재실측 반복 |
| **FAIL (구조막힘)** | 아래 (a) 또는 (b) **하나만 충족** — 4주 대기 불필요(단 (a)는 4주 경과 후) | R2 착수 금지 유지 · R1b(CAT-C)는 디렉터 승인 후 별도 대화 |

**FAIL 근거 (a)/(b)**
- **(a)** **4주 경과 후**에도 OPEN=0 지속 (본 §3 Kill R1 행 · 신규 상수 아님)
- **(b)** `short_funnel`에서 후보는 생성되나(`blocked_short_total`&gt;0 등 진입 직전 거절 이벤트) OPEN으로 이어지지 않는 패턴이 **반복** 관측 (SHORT 가시성 위주 · LONG `blocked_today` 미보유는 R1b 참고)

**기록:** 매주 `05_진행로그` · `CURSOR_TO_CLAUDE`에 **숫자만** (OPEN · CLOSED · short_funnel blocked 있으면 함께). 코드 diff 없음.

**참고:** LONG `blocked_today` 텔레메트리 없음(LS-GOAL-UX: SHORT만) — 수정 요구 아님 · R1b 설계 시 참고.

## 6. R1a 관측 절차 (코드 변경 금지)

서버에서만 (디렉터 또는 SSH):

```bash
DATA="${BITGET_DB_STORAGE_PATH:-/var/lib/quant-bitget/data}"
sqlite3 "$DATA/bitget_market_data.sqlite" \
  "SELECT status, COUNT(*) FROM bitget_forward_trades GROUP BY status;"
```

- OPEN=0 + CLOSED&gt;0 → 배선 생존 · **신규 진입 대기/정체** 후보 (냉시동 vs 막힘 추가 관측)
- OPEN=0 + CLOSED=0 장기 → 배선/DNA 재확인
- 결과만 `05_진행로그` · `CURSOR_TO_CLAUDE`에 기록 — **코드 diff 금지**

### R1a FASTCHECK 절차 (B1-LADDER-R1a-FASTCHECK · read-only)

> **의도**: 위 §6 수동 SQL·§3 판정표를 **매주 자동 집계**만 한다. 신규 판정 로직·게이트·R1b 자동 착수 **없음**.  
> **코드**: `bitget/observability/b1_ladder_fastcheck_bg.py` · kill-switch `B1_LADDER_FASTCHECK_ENABLED`  
> **출력**: `ops_events` 이벤트 `b1_ladder_fastcheck_weekly` — **market_type(SPOT/FUT)별 1건**, 합산 금지.

| 신호 | 소스 (재사용) | 판정 기여 |
|------|---------------|-----------|
| `open_count` | §6 SQL (+ `market_type` 분리) | OPEN&gt;0 → **PASS** |
| `closed_weekly_delta` | 동일 SQL + `COALESCE(exit_date,entry_date)` **window_days** 필터 | 최근 추이 · R6 페이스 환산 입력 |
| `blocked_short_total` | `short_funnel_report_bg` 기존 출력 **인용**(재계산 금지) | FUT만 유의미 · SPOT SHORT 구조적 0 · **반복** 시 FAIL(b) |
| `r6_pace_flag` | `(Δ ÷ window × 56)` vs R6 `trades≥30` | **"페이스부족" 표시만** — R6 게이트 미변경 |

**verdict 대입 순서 (§3 표 그대로):** PASS → FAIL(b) 반복(직전 weekly + 이번 OPEN=0∧blocked&gt;0) → FAIL(a)(R0+4주·OPEN=0) → 관측유지.

**금지:** FAIL(b)만으로 R1b(CAT-C) 코드 착수 · live/Kelly/MDD/gates 변경 · SPOT+FUT 합산 서술.

## 7. B0-SAMPLE-CONTRACT — 표본 충분성 계약

> **sub-phase**: B0-SAMPLE-CONTRACT · **문서 전용** (코드·config_kv·게이트 비접촉)  
> **의도**: R1a **PASS 문턱**(OPEN&gt;0 = 계측 정상)과 R6 **검증 문턱**(trades≥30 · ≥56일) **사이 간극**을 메우는 계약.  
> **비변경**: §1~§6 · Kill표 · R6 숫자(재사용만).

### 7.1 정의 배너 (Kill 표기 · `14_` §3 패턴 재사용)

모든 FASTCHECK 산출물 상단 고정:

> **PASS = 계측 정상 작동. 표본 충분성은 §7.2 기준 별도 판정.**

→ 「FASTCHECK PASS = B1 검증 완료」 서술 **금지**.

### 7.2 페이스 기준 (연산만 · 신규 상수 아님)

```
목표_주간페이스 = 30 ÷ 56 × 7
```

(§2 R6 `trades≥30` / `≥56일` 그대로 주간 환산.)

기존 FASTCHECK 출력(`r6_pace_flag` / 환산값)을 위 기준과 비교 → **페이스 경고 라벨만** (게이트 아님 · 표시 전용).

### 7.3 R1a PASS 이후 관측 (신규 게이트 아님)

- R1a **PASS**(OPEN&gt;0, §3 비변경) → **R2 착수 유지**.
- R2 진행 중 페이스 경고가 연속 발생하면 `05_진행로그` · `CURSOR_TO_CLAUDE`(해당 레인)에 **표시만** 추가 — 코드·게이트 불변.

### 7.4 트리거 표 (기존 정책 조합)

| 조건 | 경로 | 형태 |
|------|------|------|
| R1a **FAIL(b)** 확정(§3) | **(A)** R1b CAT-C | 그때만 별도 Handoff |
| PASS / 관측유지 + 페이스 무관 | 대기 | 코드 없음 |
| (병행) | **(B)** FULL-BT L1 | `LANE_HIST3FIX` 유지 · R6/B1 **대체 금지** (`15_` SSOT) |
| R2 종료 시점에도 페이스 경고 **4주 연속** AND FAIL 아님 | **(C)** 목표 재협상 | 디렉터 Ask 상정만 · B1 12~18% **숫자 변경은 범위 밖** |

### 7.5 금지 재확인

게이트 완화 · 가짜 거래 강제 · `ENABLE_REAL_EXECUTION` · 「FASTCHECK=검증완료」 과신 서술 — **전부 유지 금지**.

SPOT/FUT: **공통** · market_type 분리 집계만 · 합산 금지 · SPOT SHORT=0 기존 각주 재사용.

**롤백:** 본 §7 섹션 삭제만 — 코드·config 영향 없음.
